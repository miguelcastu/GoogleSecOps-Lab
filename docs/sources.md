# Source and UDM mapping

Each JSONL record contains **source**, **origin** and **raw**. Choose **synthetic** for lab records and pass **--allow-real** only for approved real exports. **secops-lab normalize** emits raw, parsed and UDM in separate fields. All mappings below describe a supported export subset. Vendor parsers can assign different product names, event classifications and identity fields. [Checked-in fixture dataset](../datasets/synthetic.jsonl) · [UDM field list](https://docs.cloud.google.com/chronicle/docs/reference/udm-field-list) · [UDM usage guide](https://docs.cloud.google.com/chronicle/docs/unified-data-model/udm-usage)

| Source | Supported input | Mapping |
| --- | --- | --- |
| gcp_audit | Cloud Audit Logs LogEntry with the AuditLog protoPayload type | timestamp → eventTimestamp, insertId → productLogId, principalEmail or principalSubject → principal.user.userid, callerIp → principal.ip, resourceName → target.resource.name, methodName → productEventType, status.code → securityResult.action. Recognized Logging and firewall operations map to SETTING_MODIFICATION when a caller address exists. |
| gcp_iam | Same envelope, with iam.googleapis.com or cloudresourcemanager.googleapis.com | Same fields. SetIamPolicy maps to RESOURCE_PERMISSIONS_CHANGE and CreateServiceAccountKey maps to RESOURCE_CREATION. The lab matches operations and does not calculate entitlement deltas. |
| workspace | Reports activity, one event per record | id.time, id.uniqueQualifier, actor.email → target.user.userid for login, ipAddress → principal.ip, event name → type and action. Workspace is the authentication application. |
| entra | Graph-style sign-in JSON | createdDateTime, id, userPrincipalName → target.user.userid, ipAddress → principal.ip, location.countryOrRegion → principal.location.countryOrRegion, status.errorCode → action. |
| windows | Security 4624/4625, JSON export with EventData | TimeCreated, EventRecordID, TargetUserName → target.user.userid, Computer → target.hostname, IpAddress → principal.ip when available. |
| sysmon | Events 1, 3 and 13, JSON export with EventData | TimeCreated, EventRecordID, Computer → principal.hostname, User → principal.user.userid. Image and CommandLine describe target.process for event 1, parent Image describes principal.process, event 3 maps addresses and destination port, and TargetObject maps to target.registry.registryKey. |
| linux | OpenSSH message with an RFC3339 collector timestamp | timestamp, hostname → target.hostname, user → target.user.userid, source address → principal.ip, Accepted or Failed → action. |
| falcon | Falcon DetectionSummaryEvent subset | eventCreationTime in epoch milliseconds, DetectId, UserName → principal.user.userid, ComputerName → principal.hostname, FilePath and CommandLine → target.process. |
| fortigate | Forward traffic with a collector timestamp | srcip, dstip and dstport → principal and target endpoints, sentbyte → network.sentBytes, LAN-to-WAN interfaces → OUTBOUND, accept or deny → action. |
| dns | Zeek-style DNS JSON with an RFC3339 collector timestamp | ts, id.orig_h, id.resp_h, query → network.dns.questions.name. |
| proxy | Structured HTTP proxy export | timestamp, request_id, user and client_ip → principal, absolute URL → target.url and target.hostname, upstream_ip → target.ip, method → network.http.method, request_bytes → network.sentBytes. |
| cloudtrail | One CloudTrail record per envelope | eventTime, eventID, eventName, userIdentity.arn → principal.user.userid, IP → principal.ip, role or bucket → target.resource.name. GetObject maps to RESOURCE_READ. AttachRolePolicy and PutBucketPolicy map to RESOURCE_PERMISSIONS_CHANGE. |
| webhook | Generic JSON event envelope for offline replay | timestamp, id, action, actor, source_ip and resource → GENERIC_EVENT. Use an authorized export to feed the file collector. |

Timestamps must include an offset and normalize to UTC microseconds. The normalizer preserves only observed or classifying values, such as protocol DNS for a DNS query. UDM validation covers the emitted subset. Importing an event into a licensed instance adds Google-side schema, retention and field checks.

Google's native parser guides informed the normalization boundaries. For example, the Azure sign-in default parser documents the use of email addresses and provider IDs under the principal. The lab profile instead uses a target login identity for correlation. Reconcile this difference and product identifiers against native sample UDM before enabling rules.
